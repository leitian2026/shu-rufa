# 搜猪输入法(拼音 / 笔画 / 英文)

自用 Android 输入法。只申请联网权限(用于「词库管理」下载词库,以及打开「输入翻译」后调用微软 / 谷歌翻译;翻译没打开时键盘不联网),零第三方依赖,Kotlin 自绘键盘。

## 构建(只能手动触发)

1. 把本目录推到 GitHub 仓库。
2. 仓库页 → **Actions** → *Build release APK (manual)* → **Run workflow**。
3. 跑完后在该次运行页底部的 Artifacts 下载名为 `myime-v版本号-build序号` 的产物,解压得到 `app-release.apk`。
4. 手机安装 → 打开「搜猪输入法」App → 按两个按钮启用并切换。

不会自动构建:工作流只有 `workflow_dispatch` 触发器。

### 签名与覆盖安装
覆盖安装需要三件事同时满足:**包名不变、签名密钥不变、versionCode 只增不减**。

- 包名固定为 `com.example.myime`。
- 签名:密钥**不在仓库里**,全部从环境变量读取(GitHub Secrets):`KEYSTORE_BASE64`(.jks 文件的 base64)、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD`。每次构建都用同一把,后续版本才能覆盖安装。
- 备份密码同样来自环境变量 `BACKUP_PASSWORD`(Secret),构建时编进 `BuildConfig`。
- 仓库 Settings → Secrets and variables → Actions 里添加以上 5 个 Secret;缺任何一个,release 构建会直接报错。
- versionCode 由版本号加 CI 运行序号自动算出,同一版本号重复构建也会继续增大。
- 换了密钥后,手机上用旧密钥装的版本必须先卸载一次。

```
keytool -genkeypair -v -keystore release.jks -alias myime -keyalg RSA -keysize 2048 -validity 36500
base64 -w0 release.jks        # macOS: base64 -i release.jks
```

### 版本号怎么改
只改根目录 `version.properties`,格式是 **主版本.次版本.修订号**(例如 1.4.2):

| 改动类型 | 怎么升 | 例子 |
|---|---|---|
| 大版本:大改版、重大功能变化 | 主版本 +1,次版本和修订清零 | 1.4.2 → 2.0.0 |
| 小版本:新增功能,向下兼容 | 次版本 +1,修订清零 | 1.4.2 → 1.5.0 |
| 修订:只修 bug、调细节 | 修订 +1 | 1.4.2 → 1.4.3 |

- 还没稳定时用 `0.x.y`,觉得可以长期用了再发 `1.0.0`。
- 不用手动管 versionCode,构建时自动计算:`主×10,000,000 + 次×100,000 + 修订×1,000 + 构建号`。
- 每次构建的产物名里带版本号和构建序号,如 `myime-v0.1.0-build3`,方便对应。

## 界面与使用
界面排版和配色参考你给的截图:浅蓝灰键盘底、白色按键带底部阴影、功能键偏深、蓝色主按钮。

- **上方两条白色区域**:上条是拼音/笔画预览;下条空闲时是工具栏,输入时换成候选词(第一个蓝色)。
  工具栏 6 个图标,从左到右:**设置**(打开本应用)、**切换输入法**、**表情**、**光标编辑**、**剪贴板**(剪刀图标)、**收起键盘**。当前打开的页面对应的图标会高亮。
- **拼音页**:26 键,键帽大写。左下角「笔画」键切到笔画;输入中它变成「分词」,用来标出音节边界(如 `xi'an`);底行的「符」变成「笔筛」,见下面「拼音里的笔画筛选」。
- **笔画页**:横 一(h) 竖 丨(s) 撇 丿(p) 点 丶(n) 折 ㄥ(z);`*` 是通配任意一笔;`ab` 切回拼音;左侧竖排标点键(，。？！…);打了笔画后「符」换成「分字」(打词,见「第 12 次」),「123」换成「整字」(只要刚好这么多画,见「第 13 次」);长按候选看读音和笔画数。
  宽屏(平板/横屏)左边多一块数字区,和截图一致。输入中右下角的回车键变成「清除」。
- **中/英**:在最近用的中文方式和英文之间切换。**符**:符号页;**123**:数字页。
- **光标编辑页**(工具栏第三个图标):页首(原 Tab,跳到整段文字开头)、复制、粘贴、剪切、全选、方向键、开头/末尾、Del;点中间的「选择」后,上/下箭头每点一下向上/下多选一行(落在同一列,行短到行尾),左/右箭头每点一下多选一个字,开头/末尾选到行首/行尾,页首一路选到文字开头(直接改选区,不靠 Shift 键;只在点按时读光标附近各 2000 字,无轮询,应用不支持时退回发方向键);右下蓝色「返回」。
- **表情面板**:共 700 多个、8 个分类,上下滑动;点底部分类标签会带动画滚动过去;最近用过的排在最前面(只存内存)。分类和表情可以直接改 `app/src/main/assets/emoji.txt`。
- **剪贴板**:自动记录你复制过的文字(最近 30 条,新的在前)。点一条 = 粘贴并回到键盘;点右侧 × 删除这一条;右下「清空」删除全部。
  只保存在内存里,进程结束就没有了,不写入存储;密码管理器等标记为"敏感"的复制内容不会被记录。
  只有本输入法是当前使用的输入法时才能读取剪贴板(系统限制)。
- 空格选第一个候选;回车在有输入时原样上屏;删除键和方向键长按连发。
- 密码框强制英文且不使用组合区;数字/电话框直接进数字页。

## 输入翻译
- **打开 / 关闭**:工具栏第一个按钮(功能页)里的「翻译微软」或「翻译谷歌」:点哪个就用哪个引擎打开输入翻译,正在用的那一格整格变成**绿底白字**,另一格保持原样;主用引擎失败自动换备用时,绿色跟着换到备用那一格,主用那格变回原样;再点同一格关掉,正开着微软时点「翻译谷歌」= 直接换成谷歌。打开后(键盘其他地方配色不变),翻译框和悬浮键盘顶上的拖动条也用绿色,一眼能分辨现在是不是翻译状态。再点一次关掉。开关会记住。
- **翻译框**:打开后候选栏上面多出一行:`[中›英] [ 原文…… ×] 完成`。键盘(拼音 / 笔画 / 英文 / 表情 / 符号 / 剪贴板)打的字都先进这个框,**停下约 0.35 秒就翻译,译文实时出现在目标输入框里**(带下划线,下一次译文直接替换它)。
- **完成**:点框右边的「完成」或键盘上的回车键(有字时它显示「完成」)——译文留在目标输入框里,翻译框清空,输入结束。翻译框是空的时候,回车键照常是目标输入框的「搜索 / 发送 / 换行」。译文还没回来就点完成,会等它回来再收尾。
- **×**:清空原文,目标输入框里的译文一起清掉。框空时右边是「关闭」,等于关掉输入翻译。
- **方向**:点左边的 `中›英` 换下一个方向(中›英 → 英›中 → 中›日 → 中›韩 → 中›法 → 中›德 → 中›俄 → 中›西),框里有字会马上按新方向重翻。
- **引擎**:功能页的「翻译微软 / 翻译谷歌」两个键,点哪个哪个就是**主用**(会记住)。默认微软(Edge 浏览器内置翻译的接口,国内能直连);主用失败(超时 / 被拒)自动换另一个试,刚失败过的引擎 1 分钟内先放到后面,不会每个字都等它超时。同一句话翻过的有缓存,不再联网。
- **只在普通文本框里用**:密码、数字、电话、邮箱框不翻译。点了应用里别处(光标离开译文),就结束这一次翻译,译文留在原来的框里。
- **省电**:没有任何定时轮询,只有「翻译框的原文变了」这一个触发。
  - 停 0.6 秒才发请求,连续打字不会每个字都联网(`TRANS_DEBOUNCE_MS` 可调,越长越省)。
  - 一次只发一个请求;排队里已经过期的、以及要换备用引擎前原文已变的,都不再发。
  - 连接读完不断开,复用系统连接池,省掉每次的 TCP + TLS 握手;超时 4 / 6 秒;微软令牌缓存约 10 分钟。
  - 发请求前先看有没有网,没网直接标「翻译失败」不空等超时,并只在没网时临时挂一个网络回调,网络一回来重试一次就摘掉。
  - 键盘收起时丢掉没发出的翻译、放掉请求和网络回调;再打开时才补翻。
  - 翻译框只在内容有变化时重画,打字过程中不重新排版。
- **隐私**:只有翻译框里的原文会发出去(发给微软或谷歌),目标输入框里别的内容不会读取、不会发送。

## 词库
`app/src/main/assets/` 里是启动用的**小样本**(约 220 词、66 字),只够验证流程。
换完整词库(Rime 格式):
```
python3 tools/convert_rime_dict.py pinyin app/src/main/assets/pinyin.txt 8105.dict.yaml base.dict.yaml
python3 tools/convert_rime_dict.py stroke app/src/main/assets/stroke.txt stroke.dict.yaml
```
词库越大,启动加载越慢、APK 越大,建议从单字表 + 基础词库开始。
雾凇拼音是 GPL-3.0,若基于它的数据公开发布,需遵守 GPL。

## 动画与流畅度
- 所有动画共用 `Motion.kt` 里的 **360ms + 同一条缓动曲线**(范围 300–450ms),要整体调快慢只改一处。
- 动画只改 alpha / translationY,不触发重新布局;键盘高度在所有模式下相同。
- 键盘整体是一个自绘 View,`onDraw` 不分配对象;按键高亮消退按帧时间统一推进。
- 词库查询在后台线程,不占用主线程。
- 候选栏的惯性滑动用的是系统 OverScroller,属于物理滚动,不受固定时长控制。

## 已知限制 / 后续
- 还没有候选词展开面板、主题自定义;拼音没有双拼和九键(见下面「拼音引擎总览」)。整句输入、中文联想、造词都已经有了。
- 表情不含肤色、组合(家庭、职业)类的复杂表情;显示依赖系统的表情字体。
- 手机屏幕(宽度 < 600dp)用紧凑尺寸,笔画页没有数字区。
- 自带笔画样本为手工录入,笔顺以正式字表为准。
- targetSdk 为 34,避免 Android 15 强制全屏边到边布局影响键盘底部。

### 数据安全(0.10.0)
- **安全写入**:学习数据、固定词保存时先写临时文件并刷盘,再原子替换主文件,同时留一份上一次完好的 `.bak`。以前是"先删后改名",中途被杀会丢文件。
- **读取不会越读越坏**:文件被截断、有坏字节、空文件时,自动退回 `.bak`;坏的那份另存为 `.corrupt` 留底,不会被下一次保存盖掉。保存时只有主文件确认完好才会更新 `.bak`,不会把坏文件复制过去。
- **省读写**:自己刚写成功的文件,下次保存前不再整文件重读校验(长度和修改时间没变就认为完好),每次保存少读一遍文件。
- **格式版本**:数据文件第一行 `#v1`、最后一行 `#end`(用来发现被截断)。遇到比自己新的版本,先另存一份 `.vN` 再读,旧版本不会悄悄吃掉新版本的内容。升级前的老文件(没有头尾)照常读。
- **剪贴板和回收箱会落盘**:历史(最多 500 条)和回收箱(最多 10 条)存在 `files/user/clips.txt`、`trash.txt`,切换输入法、进程被回收、重启手机后都还在。只在内容变了(复制、点用、删除)时由后台线程写一次,没有定时保存;键盘隐藏和服务销毁时补存。被系统标记为敏感的复制内容(如密码管理器)不记录。
- **笔画排序**:(第 12 次起先分字形档,见下)笔画数刚好等于已输入笔画的字(打完整个字)排在还没打完的字前面,各自再按字频、我的选择排;以前字频排在前面,刚好 3 笔但字频不够高的字(如「么」)会被后面成百上千个更长的常用字挤出前 80 名。
- **剪贴板上锁(0.17.0)**:长按一条进入多选后,每条右边出现一个小锁,点锁 = 上锁 / 取消上锁。上了锁的条目删不掉(全选、删除都会跳过,也选不中),也不会被"超过 500 条挤掉最旧的"挤掉;不在多选里时,上了锁的条目右边留一个实心小锁,点条目照常粘贴。回收箱里没有锁。上锁信息存在 `clips.txt` 里(行标记 `k`,和剪贴板同一个加密文件,老版本读到会跳过),随备份一起还原。
- **一屏 9 条**:短内容(单行)的剪贴板/回收箱一屏正好 9 条占满,字体不变,只按屏高调整卡片上下内边距和间距;标题行压紧(按键和标题文字等高,上下留白缩小),把空间让给列表。
- **剪贴板不给别的 app 读**:复制的文字一进输入法历史,系统剪贴板就被清空,别的 app(含系统自带的)再读只能读到空白;内容只在输入法私有目录里,只有你在剪贴板页点某一条才会输入到输入框。光标编辑页的「粘贴」键也改成粘贴历史里最新的一条。密码管理器标记为敏感的、超长的、非文字的内容不动。做不到的:系统本身和 root/Xposed 级别的程序,以及复制那一瞬间(几毫秒)正好在读的程序。
- **剪贴板写盘省电**:只记哪个文件变了、只写变了的那个;新复制/删除 2 秒后写一次(期间多次改动合并),点用后挪到最前这种只调顺序的等键盘收起再写;不轮询。打开剪贴板页不再多读一次系统剪贴板(复制时已经收进来了);500 条文字重排版只处理每条开头 400 字。
- **写文件不再排在候选查询前面**:保存学习数据、固定词、剪贴板都在单独的线程里做(写文件要等磁盘落盘,可能几十毫秒);候选查询的线程只做计算。诊断日志默认关闭、零开销;排查卡顿时先 `adb shell setprop log.tag.MyIme DEBUG` 再重启输入法,logcat(标签 MyIme)里就有:服务启动、键盘弹出时词库是否已在内存、词库加载耗时、单次查询超过 40ms 的记录。

### 备份与还原(0.11.0 起只有两种去处,不用设备份密码,首页第 4 个按钮)
- **备份只有两个选项**:①**备份到本地**:系统的「新建文件」选择器,存到手机上任意文件夹,是单个加密压缩包(`.mybk`);②**备份到坚果云**:通过 WebDAV 上传同样的加密压缩包(云端**每台设备各保留最近 7 份**)。0.10.0 的「选文件夹」「网盘文件夹」「导出 / 导入」已去掉。
- **还原也是两个**:①**从本地压缩包还原**:选 `.mybk`,自动解密、解压、还原;②**从坚果云还原…**:点一下弹出设备列表(每台设备最新的一份,显示设备名、备份时间、大小),选一台点「还原」,自动下载并还原。本机的排第一并预选,选好直接还原;新手机没有本机的备份,不预选,要自己点选;选别的设备或旧版备份会多确认一次。不用输密码,任何手机上都能直接解开(换手机时先设置好坚果云账号再还原)。
- **几台设备共用一个文件夹(0.15.0)**:手机、平板可以填同一个坚果云文件夹。备份文件名是 `myime-backup-<设备名>.<标识6位>-<时间>.mybk`(旧版 0.14.0 及以前没有设备名,在列表里显示为「旧版(未标记设备)」,不会被清理)。设备名默认取系统「设备名称」(读不到用蓝牙名、再不行用厂商 + 型号),可以在「设置坚果云账号」里改,留空就跟着系统走;文件名里只留字母、数字、汉字和下划线。「是不是本机的备份」只看标识(设备 ID 前 6 位,存在不进备份的 `backupcfg`),所以改名后以前的备份仍然算本机的;还原到另一台设备也不会带过去(两台设备不会共用标识)。清理旧备份只清本机的。省电:列表只在点「从坚果云还原」时列一次目录,备份时清理旧备份用的是上传后核对大小那次列目录的结果,没有多发任何请求。命名和分组逻辑在 `BackupNames.java`(纯 JDK),测试:`tools/BackupNamesSelfTest.java`(运行方法写在文件开头)。
- **坚果云设置**:在坚果云网页端「账户信息 → 安全选项 → 第三方应用管理」生成**应用密码**(不是登录密码),在备份页填账号(登录邮箱)、应用密码、备份文件夹(默认 `myime`,不存在会自动创建;顶层文件夹若坚果云不允许创建,先在坚果云里建好)。应用密码用 Android Keystore 里取不出来的密钥加密后存本机,不进备份。
- **联网**:只有备份 / 还原坚果云、测试连接、自动备份时才联网,只连 `https://dav.jianguoyun.com/dav/`,校验证书和主机名。WebDAV 客户端是自己写的纯 JDK 代码(`WebDavClient.java`,因为 `HttpURLConnection` 不支持 PROPFIND / MKCOL),没有加第三方库。坚果云免费版限制:每 30 分钟 600 次请求,单文件 500 MB。
- **备份内容(自动发现,默认全部)**:应用数据目录里的所有文件(学习数据、联想数据、英文固定词、剪贴板历史和回收箱)和所有设置文件(键盘尺寸、悬浮键盘记忆、词库设置、翻译接口设置等)。只排除:**可下载的词库包**(手动备份时可勾选包含)、**可重建的缓存**、**设备专属的数据**(坚果云账号、备份密码的包装)。
- **以后新增功能自动纳入**:新功能的数据只要放在应用数据目录(`filesDir`)或 SharedPreferences 里,就自动进备份、自动能还原,不用改备份代码。纯缓存放 `cacheDir`,或在 `BackupScope.java` 里登记一行排除。如果新功能在内存里攒数据、延迟写盘,调用 `BackupManager.addFlusher { ... }` 登记一个立刻落盘的函数。还原时条目路径会做安全检查,不能写到应用数据目录之外。
- **加密**:固定密码(`BackupVault.defaultPassword()`,构建时从环境变量 `BACKUP_PASSWORD` 读入 `BuildConfig`,不写在源码里),不用设置、不用记、不会忘。密码经 PBKDF2-HMAC-SHA256(60 万次迭代、随机盐)得到主密钥,每个文件再派生独立密钥,AES-256-GCM 分块加密、各块独立认证,改一个字节、调换或截断都会被发现。**注意**:密码会编进安装包,有决心的人能提取出来,所以防的是「别人随手打开看内容」;想要更强,可以改成用户自设密码(0.10.0 的做法)。0.10.0 / 0.11.0 早期版本里用自设密码做的旧备份,新版解不开。
- **写完即校验**:本地备份写完马上读回解密一遍;坚果云备份先在本机临时文件里解密校验,上传后再核对云端文件大小,不通过会删掉残缺文件并提示。
- **自动备份与省电**:开关在备份页(只传坚果云)。没有定时器、没有常驻线程。只在键盘收起时按从便宜到贵的顺序判断:开关 → 距上次满 24 小时(失败 6 小时,没变化 6 小时后再看) → 系统省电模式或电量低于 20% 且没在充电时跳过 → 数据文件修改时间有没有变。并且只在 Wi-Fi 等不计流量的网络上才传(不为备份唤醒移动数据,不在 Wi-Fi 时 1 小时后再看)。全部满足才另开低优先级线程备份一次(不含词库包)。上传只用 3 次请求(查文件夹、上传、列目录核对并清理旧备份)。密码是内置的,密钥迭代次数用最低值 10 万次,首次生成密钥和每次还原的 CPU 开销是原来的约 1/6。
- **还原的安全**:先完整解密并校验、放进临时目录,通过后才替换现有数据(密码错或文件损坏时现有数据不动)。替换前把会被改动的文件和设置复制到应用内 `user_before_restore/`。完成后输入法进程会重启一次。
- **签名密钥**:不在 App 里管理,也不进备份;它来自构建环境变量(见上面「签名与覆盖安装」),请自己另存一份 .jks 和密码。

## v0.12.0:词字排序改成「选了就排第一」

- **选一次就排到最前面**:拼音、笔画、中文联想里选的每个词,马上排到最前面,同一个编码下旧的往后挤一位。以前要选很多次才慢慢排上来(次数取对数加到词频上),现在选几十个常用字之后,前 10、前 20 个就都是自己的字。
- **不再有衰减**:数据里不再存次数,只存「最后一次选它是什么时候」(毫秒时间戳,本机内严格递增)。老的选择被新的往后挤,自然沉下去;超过 2 万条时删最久没用的(以前是删次数最少的)。
- **排序层级**(越靠前越大):① 这个编码下选过的 → ② 跟在上一个+上上个词后面我接过的 → ③ 跟在上一个词后面我接过的 → ④ 这个词在别的编码下选过的 → ⑤ 词典词频。拼音原来的四段匹配顺序(完整拼音精确 → 首字母精确 → 前缀 → 首字母前缀)不变,只在每一段内部重排。笔画:我选过的排在所有没选过的前面。
- **同音高频字不乱跳**(的/得/地、他/她/它、做/作/坐):同一个编码下,先比「最近 5 次选择里出现几次」,次数相同再比最近一次的先后。所以 的 ×4、偶尔选一次 得,「的」仍然第一;连着选「得」,它在窗口里占多了就自然换到第一。没有这种情况时,和「最近选的最靠前」完全一样。每个编码只多存最近 5 次。
- **中文联想**:我接过的词最近接的最靠前,两词上下文(上上个+上一个)命中的排在一词上下文命中的前面,再后面是词典里以它开头的词。
- **老数据自动迁移**:0.11 及以前存的是次数,第一次读到时按次数从小到大换成先后(都比真实时间早),次数多的排前面,之后自动重写成新格式。每个编码的「最近 5 次」窗口也按旧次数占比填好初值(的 100 次、得 3 次 → 窗口里是 的 ×4),所以升级后偶尔选一次「得」不会直接跳到「的」前面;只选过 1 次的词只占 1 个位置,稀疏的编码下新选的词仍然直接排第一。**升级后不能再降级**:旧版本读不懂新格式,降级等于没有学习数据。
- 时间戳而不是计数器,是为了以后几台手机合并习惯:合并时每个词取较大的时间、窗口取并集即可,重复合并结果不变(现在还没做合并)。
- **英文不变**:英文的学习、联想、固定词都照旧。
- 代码:`UserFreq`、`UserChain` 搬到各自的 Java 文件(纯 JDK),可以在电脑上单独测试:`tools/RankSelfTest.java`(60 项:选了就第一、的/得窗口、层级、时间戳递增、存盘重读、旧格式迁移、超限淘汰、接词、非法字符)。运行方法写在文件开头。

  - 开(默认):复制后收进输入法历史并清空系统剪贴板,别的 app 读不到。
  - 关:只收进历史,不清空,系统剪贴板照常可用。键盘再次弹出时,系统剪贴板里没变的内容不会重复顶到最前面。
  - 粘贴不了的 app:关掉开关,点历史里那一条输出到输入框,再选中复制一次,内容就留在系统剪贴板里了。
  - 带 `IS_SENSITIVE`、非文字、超长(5000 字)的内容照旧不收、不清。
- **光标编辑页的复制 / 剪切**:开关开时用 `getSelectedText` 读出选中的文字直接存进历史,不碰系统剪贴板(剪切再发一个删除键);
  开关关、读不到文字(密码框、部分网页和自绘编辑器)、超长时,退回让 app 自己复制 / 剪切。密码框一律退回 app 自己处理。
- **粘贴失败提示**:点历史里的条目时 `commitText` 失败(或没有输入连接)会弹提示并留在剪贴板页。有的 app 强制自带键盘(银行、支付密码框),
  我们的键盘根本不出现,弹不了提示,所以剪贴板页常驻一行小字写明办法。这一行占一个位置,剪贴板页一屏 8 条,回收箱仍是 9 条。
- **加密存储**:`clips.txt`、`trash.txt` 里是一行 `E1<Tab>Base64(随机数+密文)`:AES-256-GCM,数据密钥随机生成,用 Keystore 里取不出来的密钥包起来存在 `backupcfg`(不进备份)。
  老版本的明文文件照常读,读到后自动改写成加密的。Keystore 密钥丢了解不开就当空历史重新开始;Keystore 用不了的机器退回明文保存。
- **备份**:剪贴板两个文件进备份。备份时先解成明文再放进(已加密的)备份包,还原到新手机后第一次启动自动重新加密。本机解不开的文件不放进备份。

## 多台手机同步学习数据(0.14.0)
几台**都是自己的手机**共享词频学习数据,打得越多越准。备份与还原页的第 4 部分。

- **只同步这些**:拼音的选词记录、笔画的选词记录、中文联想词。剪贴板、回收箱、设置、翻译配置、英文用词、坚果云账号都不同步。代码里是白名单:同步模块只拿得到这三个对象(`LearnShare`)。
- **怎么合并**:学习数据存的是\"最后一次选它的时间\",合并只取较大的时间戳(每个编码最近 5 次的窗口取两边最新的 5 个)。所以顺序无关、重复合并结果不变,不需要谁当主机。别的手机时间偏快时,超过当前时间的时间戳会被截成当前时间。
- **怎么传**:复用备份的坚果云账号和文件夹,每台手机只写自己的 `myime-learn-<设备ID>.lrn`(gzip 压缩 + AES-256-GCM 加密),从不改别人的文件,没有写冲突。读别人的文件前先列一次目录,大小 / 修改时间 / 版本标记没变的不下载。上传前先读回解密校验,上传后核对云端大小。解不开的文件(别的构建、损坏、格式太新)跳过,不报错、不删除。
- **加密密钥自动**:用内置的备份密码(`BACKUP_PASSWORD`)加固定盐算出同步密钥,不用手输;和备份密钥是两把不同的密钥。前提:几台手机装**同一个构建**,并且都设好了坚果云账号;`BACKUP_PASSWORD` 用过就不能改。强度和现有备份一样(防的是随手打开网盘看到内容,防不了有安装包又愿意去逆向的人)。
- **什么时候同步**(没有定时器、没有后台常驻,只在键盘事件上做几个便宜的判断):
  - 键盘收起:自上次上传以来新学 ≥300 次且距上次上传 ≥1 天;或有新学的、距上次上传超过 7 天;从没上传过且本机有数据 → 先拉取合并,再上传。
  - 键盘弹出:距上次拉取 ≥1 天 → 拉取一次。
  - 不在省电模式、电量够(沿用自动备份的判断)、有网;**Wi-Fi 和流量都可以**。失败不连续重试,6 小时后再说;没网 1 小时后再看。
  - 备份页有「自动同步学习数据」开关和「立即同步学习数据」按钮(不看时间和攒了多少,拉取 + 上传都做)。
- **导出过滤**:词里含数字或 4 个以上连续英文字母的条目不共享(防手机号、账号、密码混进去);编码不过滤。
- **还原备份后重新合并(0.15.1)**:从备份还原会把本机学习数据整个换成备份里的内容,可能缺了之前已合并过的别的设备的数据;而同步会跳过「没变化、已合并过」的远端文件。所以还原成功后,`LearnSync.afterRestore` 清掉本机记着的这些「已合并」标记并把上次拉取时间归零,下次键盘弹出时重新下载、合并别的设备的文件(只补缺的,不覆盖)。只清本机 `backupcfg` 里的记录,不动云端和学习数据;只在还原那一刻做一次,平时同步节奏不变。
- **清除学习数据只清本机**:在这台手机上清除后,别的手机不受影响;清除之前的记录也不会被别的手机的旧文件再同步回来(合并时丢掉时间早于清除时间的记录),清除之后新学的照常同步。
- **状态不进备份**:设备 ID、版本标记、同步密钥缓存、清除时间都放在 `backupcfg`(设备专属),不会跟着备份还原到另一台手机。同步的临时文件放在缓存目录。
- 测试(纯 JDK,电脑上跑):`tools/LearnSyncSelfTest.java`(过滤、合并、幂等、交换律、窗口、时间戳截断、坏文件、加密往返)和 `tools/LearnSyncE2E.java`(配合 `tools/fake_dav.py` 模拟几台手机走完整流程),运行方法写在文件开头。
- 英文用词(`UserEnglish`)存的是次数、不是时间戳,合并规则不同,这一版没有同步。

## 拼音引擎总览(0.25.0)

0.18.0 ~ 0.25.0 分 10 次把拼音引擎从「按拼音连写做前缀匹配」改成了「认识音节、能拼整句」的引擎。下面是**现在的样子**;每一次改动的细节和取舍见后面「拼音引擎改造过程」。

### 能做什么

| 能力 | 例子 | 开关 / 设置 |
|---|---|---|
| 音节切分 | `xian` 优先当一个音节;最后一个音节可以没打完(`zhon`) | 无,一直开 |
| ü 的写法 | `jv`=`ju`、`yve`=`yue`、`lue`=`lve`、`ü`=`v` | 无 |
| 整句输入 | `womenmingtianqukanshu` → 我们明天去看书 | 无 |
| 歧义切分 | 同一串给最多 3 种整句(`shiqu` → 是去 / 事去;`xianzai` 在 现在 后面给 先在 / 西安在) | 无 |
| 全拼简拼混打 | `zgren` → 中国人;`wmmtquks` → 我们明天去看书 | 无 |
| 模糊音 | z/zh、c/ch、s/sh、an/ang、en/eng、in/ing、l/n、f/h | 词库管理 → 模糊音(默认全关) |
| 拼错容错 | `nihoa` → 你好(写反 / 按错相邻键 / 多打 / 漏打,只改一处) | 无(只在解释不了时才试) |
| 造词 | 连续选「张」「伟」→ 记下「张伟」 | 无;词库管理里「清除学习数据」会清掉 |
| 学习整句 | 选了整句,句子里每个词和相邻词都记一笔 | 随「学习」开关 |
| 候选数量 | 每次最多 15 / 30 / 50 / 80 个词候选 | 词库管理 → 候选数量(默认 30) |
| 多机同步 | 选词记录、联想、**造的词**(加密,0.24.0 起) | 备份页 |
| 省电 | 系统省电模式下少做几件事 | 跟随系统 |

**没有做的**:双拼、九键(决定不做,不在这几次的范围里);整句动态规划按键之间的增量复用、查询结果缓存(评估后没做,理由见第 9 次);「删除某一个造的词」的入口(只能整体清除学习数据)。

### 一次查询怎么走(`PinyinEngine.queryRaw`,按候选出现的先后)

1. `ü` 别写统一成词库写法(有别写才多查一次,两种写法的结果合并去重)。输入里的 `'` 记为用户标的音节边界。
2. **我造的词**:整串正好是我的词,排最前面。
3. **词库精确**:整串的拼音连写正好等于词条的拼音连写(同音的按「我选过的 > 词频」);勾了模糊音时紧跟着是**折叠后的精确匹配**;再是**首字母精确**;然后是我造的词的补全(最多 3 个)、**前缀补全**、**首字母前缀**、折叠后的前缀补全。
4. **整句**(≥ 5 个字母):整串不是词时放最前面,最多 4 句(最多 3 种切法 + 模糊音再加最多 2 句);整串本来就是词时,输入 ≥ 6 个字母才查,最多 2 句,放在这些词后面。
5. **混拼**(≥ 4 个字母且不能切成完整音节)。
6. **拼错容错**(以上没有任何候选能吃完整串、≥ 3 个字母、没有分词符):查到的放在最前面。
7. **分段**:整串吃不完时,取最长的、能精确匹配的前缀,最多 8 个(剩下的字母留在组合区继续打)。
8. 候选后面的联想词和表情由键盘服务另外加。

每一步贵的部分开始前,引擎都会问键盘服务「这次查询是不是已经过期」(又有新按键就不做了);系统省电模式下只算最好的一句、不拼模糊音整句、拼错容错不拼整句、不在后台建模糊音索引。

### 设置在哪、存在哪

| 设置 | 位置 | 存放 | 生效时间 |
|---|---|---|---|
| 候选数量 | 词库管理页 | `dictcfg` 的 `cands`(整数 10~100,默认 30) | 下次弹出键盘 |
| 模糊音 | 词库管理页 | `dictcfg` 的 `fuzzy`(8 位按位或:z/zh=1、c/ch=2、s/sh=4、an/ang=8、en/eng=16、in/ing=32、l/n=64、f/h=128) | 下次弹出键盘;索引在后台建好后下一次按键起生效 |
| 学习开关 | 词库管理页 | `dictcfg` 的 `learn` | 立即 |
| 造的词 | — | `files/user/words.txt`(随本机备份) | 键盘隐藏时落盘 |

### 代码在哪

### 怎么测

- **一条命令跑全部自测**:在工程根目录执行 `bash tools/run_selftests.sh`(需要 JDK 17+;WebDAV 的两项还需要 python3,没有就跳过)。只跑一部分:`bash tools/run_selftests.sh Sentence Typo`(名字里带这些词的)。会给出每项的通过数和汇总,有失败就以非 0 退出。当前共 13 个测试文件、近 500 项检查。
- 每个测试文件开头也写了单独编译运行的命令。

- 新增的数据都是新文件或新设置项,**不改任何已有格式**:`user/words.txt`、`dictcfg` 里的 `fuzzy`、`cands`。同步文件版本号仍是 1,老版本读新文件会跳过 `@words`。
- 和 0.12.0 一样,**升级后不建议降级**:降级后新版本造的词不会被用到(文件还在,再升回来就恢复)。

## 拼音引擎改造过程(分 10 次,每次一个压缩包)

### 第 1 次(0.18.0):音节表 + ü 写法统一
- 新增 `Syllabary.java`(纯 JDK):约 410 个标准音节、音节前缀表、切分器 `segment()`(音节数最少优先,同样少时完整音节优先于带半截尾巴;最后一段允许没打完,如 `zhon`)。这是后面整句输入、混拼、容错、模糊音的地基,这一次先只接了 ü 的写法。
- **ü 的写法统一**:`jv/qv/xv/yv` 当作 `ju/qu/xu/yu`(`jvan`、`yve`、`xvn` 同理),`lue/nue` 当作 `lve/nve`(词库里的写法),输入 `ü` 当作 `v`。替换前后长度不变,所以「消耗了几个字母」的换算不受影响;用 `'` 手动分开的地方不会被当成一个音节(`lu'e` 不会变成 `lve`)。
- `lue` 也可能是 `lu`+`e`,所以有别写时两种写法都查,按词库写法查到的排前面,按词去重。学习记录也按词库写法记,`jv` 选过的字下次打 `ju` 也排前面。
- **功耗**:没有 `v`、`ü`、`ue` 的输入(绝大多数)只做三次 `indexOf`,和以前一样只查一次;有别写才多查一次。表是静态只读的,第一次用到时建一次。
- 测试:`tools/SyllabarySelfTest.java`(音节表完整性、内置词库每个音节都合法、切分、别写、分词符、长度不变、速度),运行方法写在文件开头。

### 第 2 次(0.19.0):整句输入
- 新增 `SentenceDecoder.java`(纯 JDK):把 `womenmingtianqukanshu` 这样的长串切成词库里的词,组成整句 **我们明天去看书**,放在候选第一位,空格直接上屏整句。
- **怎么选**:词库按拼音连写排好序,从每个音节边界出发一个字母一个字母往后延长,每次二分查「连写正好等于这一段」的词;词库里没有任何词以这一段开头就立刻停止。每个词的分 = ln(词频 ÷ 总词频) + 每多一个音节加 1 分(词库里的词比拆成单字可信);整句分 = 各词之和,维特比取最高。我打过的词加 3 分;第一个词如果是我常接在上一个词后面的再加 2 分。
- **没打完的尾巴**:`womenmingtianqukansh` 末尾的 `sh` 还没成音节,整句吃到 `kan` 为止(`我们明天去看`),剩下的留在组合区继续打。
- **用 `'` 分过的地方要遵守**:`xi'an'zai` 只会用在这些位置有音节分界的词(西安、在),不会拼成先在。
- **什么时候才算**:输入 ≥ 5 个字母、整串不是词库里的一个词、至少能切出两个词。整串本来就是一个词(中国、现在)不跑整句,和以前一样。
- **选了整句怎么学**:整句本身不在词库里,所以句子里每个词各记一笔(`我们`、`明天`、`去`、`看书` 各自排到前面);下次单独打这些词也会靠前。
- **功耗**:每次按键最多多一遍 O(字母数 × 词长) 次二分,没有后台线程、没有缓存、没有预计算;总词频只在第一次要拼整句时算一次。电脑上 20 万条词库、35 个字母的整句平均约 0.8 毫秒(手机慢一些,仍是毫秒级)。输入超过 48 个字母不拼。
- 还没做(后面几次):全拼简拼混打、`xian` 这类歧义给出多种整句、模糊音、拼错容错、造词。
- 测试:`tools/SentenceSelfTest.java`(整句、尾巴、缺音节、分词符、我打过的词、接词习惯、速度),运行方法写在文件开头。

### 第 3 次(0.20.0):全拼、简拼混打
- `SentenceDecoder.decodeMixed`:输入里有没法当成完整音节的字母时,每个音节既可以写全,也可以只写声母(`zh/ch/sh` 写 `z/c/s` 或 `zh/ch/sh` 都行),最后一个音节可以只打了前半。
  - `zgren` → **中国人**(整串也能对上的其他词排在后面,如更冷门的同声母词)
  - `zgre`(最后一个音节没打完)→ 中国人;`zhgr` → 中国人
  - `wozgr` → 我中国人;`nihaozgr` → 你好中国人(写全的和简写的可以在一个整句里混着出现)
  - `wmmtquks` → 我们明天去看书;`womenmtqukanshu` → 我们明天去看书
- **规则**:只有一个音节的词必须写全(单独一个声母太含糊,`womenq` 不会把 `q` 当成「去」);至少有一个音节是简写才算混拼,全写全的走原来的整句。整串必须全部吃完才出混拼候选,吃不完不硬凑。用 `'` 分过的地方,音节记号不会跨过分词符。
- **做法**:不展开词库。从每个能走到的位置往后找「音节记号」(完整音节或声母),每走一步用已有的首字母串排序数组二分一次,没有任何词以这个首字母串开头就停;走到记号个数够了,就把首字母串正好相同的词逐个和输入对一遍(写全的要相等、简写的要首字母对上、最后一个音节只要是前缀)。每个简写的音节扣 0.7 分,所以同样能对上时写全的排前面。
- **什么时候才算**:只有输入 ≥ 4 个字母、**不能切成完整音节**(最后一段没打完的音节除外)时才查。绝大多数全拼输入(能切成音节)不会多做任何事;2、3 个字母的纯声母(`zg`、`zgr`)还是原来的首字母匹配。输入超过 24 个字母不查。
- 选了混拼候选:每个词各记一笔(按当时打的那一段记)。

### 第 6 次(0.22.0):拼错容错

### 第 7 次(0.23.0):造词
- **什么时候造词**:同一次输入里**连续选了几段**拼音候选,拼起来词库里没有,就记成一个新词。例如打 `zhangwei`,先选「张」(消耗 `zhang`),再选「伟」,选完时就记下「张伟」。下次打 `zhangwei` 它排在所有候选最前面;打 `zhangw` 它出现在补全里(排在词库补全前面);整句里(`zhangweilaile`)也直接用它当一个词,即使词库里没有这个词也能拼出整句。
- **防止记进乱词**:
  - 每一段都是**单个字**的(人名、新词)第一次就记;有的段本身是多字词(选「我们」再选「明天」)要拼成同样的词**第二次**才出现在候选里,第一次只是记个数。
  - 每一段必须是词库里的真实读音和写法;用模糊音、拼错容错、简拼、联想词打出来的不记,免得记下错误的拼音。
  - 只记汉字,2~8 个字,词库里本来就有的不记;选中途退格或接着打字就不算「连续选词」,重新开始。
  - 每个字的拼音取自词库条目本身(所以多音字的读音是对的),存的是每个音节(`zhang wei`)。
- **存放**:`user/words.txt`(SafeFile 格式:原子写、有备份、损坏时另存),每行 `W 词 音节 次数 时间`;最多 3000 个,多了先丢还没可用的,再丢次数少又久没用的。只在键盘隐藏时落盘(和其他学习数据一样);「清除学习数据」会一起清掉;会进本机备份(备份会收 files 下所有文件)。**多机同步这一版没有同步造的词**(同步目前只覆盖选词习惯和联想)。
- **整句里怎么算分**:我造的词分数 = ln(2000 × 次数) − ln(总词频) + 每多一个音节加 1 + 我的词加 3,比词库里同样长的词高得多(这是我自己拼出来的);用 `'` 分词时词的音节边界必须对得上,否则不用。查询只读一份不可变快照,打字时不加锁,没有任何造的词时一点开销都没有。
- **功耗**:造词只在「一次输入选完、连续选了不止一段」时跑一次,在后台线程,做几次二分和一次追加;快照只在词有变化后重建一次(排序 ≤ 3000 个)。电脑上 3000 个造的词时整句平均约 0.06 毫秒。

**第 9 次:性能和功耗收尾**
- **过期查询取消**:原来排队里的旧查询已经会被丢掉,但正在算的那次不会停。现在服务在每次查询前给引擎一个「是不是已经过期」的检查(`PinyinEngine.stale`),引擎在整句、模糊音整句、混拼、拼错容错、分段这几个比较贵的步骤**开始前**看一眼,过期了就不做了(结果反正会被丢掉)。快速连打时省下的就是这些步骤。
- **省电模式**:键盘每次弹出读一次系统的省电模式(`PowerManager.isPowerSaveMode`)。开着省电时引擎少做这几件事:只算最好的一句(不查多种切法)、整串本来就是词时不再拼整句、不拼模糊音整句、拼错容错不拼整句、**不在后台建模糊音索引**(已经建好的照常用)。普通的查词、补全、混拼、纠错查词不受影响。
- **预热**:词库加载完后在后台线程把第一次长句要用的东西备好(整句解码器的总词频、音节表、拼错容错),第一次输长句时不会卡一下。
- **少算一遍**:一次查询里音节切分最多算一次(模糊音和混拼都用同一份结果)。
- **评估后没有做的**:① 缓存上一次的查询结果——打字时每次按键的输入串都是新的,命中率很低,而且结果依赖学习记录、上文、模糊音设置,缓存失效的条件很多,风险大于收益;② 整句动态规划按键之间增量复用——能省下一部分二分,但要把路径表、学习分数、词接词都做成可增量的,改动大、容易出错,而现在每次按键的平均耗时已经是毫秒级。
- **每次按键的开销(电脑上,20 万条随机词库、25 个字母的长句逐字母打;手机会慢几倍,看的是各步之间的比例)**:

  | 步骤 | 什么时候才跑 | 平均 |
  |---|---|---|
  | 查词(精确 / 首字母 / 补全) | 每次 | 毫秒以内 |
  | 整句(最多 3 种切法) | ≥ 5 个字母,整串不是一个词 | 约 0.6 ms |
  | 混拼 | ≥ 4 个字母且不能切成完整音节 | 约 1 ms |
  | 模糊音(查 + 整句) | 勾了规则、索引建好、没有分词符 | 约 1.5 ms |
  | 拼错容错 | 以上都解释不了整串 | 约 0.1 ms 找写法 + 每个写法一次查词 / 最多 3 次整句,带错字母的长句每次按键平均约 1.8 ms |
  | 造词 | 一次输入选完、连续选了不止一段 | 后台线程,几次二分 + 一次追加 |

### 第 11 次(0.26.0):拼音里的笔画筛选(音形混输)
同音字多、想要的字排得很靠后时,不用翻页,也不用切到笔画页重打:打完拼音后按几笔,把候选筛成第一个字笔顺对得上的。

  - 退格:先退一笔;笔画退完再按一下退格,关掉笔筛(拼音不动);再按「笔筛」也能关(连笔画一起清掉)。

- **筛什么**:候选词的**第一个字**,有一种笔顺是以你按的这几笔开头的(同一个字有几种笔顺,任何一种对得上就算)。多字词也只看第一个字。

### 第 12 次(0.27.0):笔画组词 + 繁体字频 / 字形偏好

**笔画组词(一个词的每个字各打一段笔画)**
- **怎么用**:笔画页打了笔画后,「符」键(宽屏在右侧功能列)换成「分字」。打完第一个字的笔画,按「分字」,接着打第二个字的笔画……预览条显示成 `一丨·丿丶`(`·` 是分字符)。候选里是「以第一段对得上的字开头、后面每个字的笔画都对得上」的词。
  - 每一段可以只打前几笔(前缀匹配),也可以用 `*`(任意一笔),和单字一样。
  - 最后一段留空(按了「分字」还没打)= 第二个字任意,只要是两个字以上、第一个字对得上的词。
  - 词比单字靠前:我选过的最前,其余字数刚好等于段数的优先,再按词频。词来自拼音词库(没装拼音词库就只有单字);第一次按「分字」才加载拼音词库,加载完自动重查。
  - 候选后面跟几个「只上屏第一个字」的单字(消耗第一段和分字符),剩下的笔画留在组合区继续打,和拼音的分段上屏一样。
  - 选词会记进「选词学习」:记在「各段笔画连起来」的编码下,同样的笔画下次这个词排在前面。
- **怎么查得快**:不扫整个词库。先用第一段笔画查出前 40 个首字候选,再在「按词排序」的下标里取以它们开头的词(每个字一段连续区间,二分定位),后面每个字用笔画反查索引核对(`StrokeIndex.matchesCp`)。一次最多看 8000 个词(`WORD_SCAN_CAP`),通过的按分数留前 30 个。电脑上 20 万词库、40 个首字、扫满 8000 个约 4 ms,手机会慢几倍。
- **功耗**:不按「分字」时和以前完全一样;按了才加载拼音词库并用那份「按词排序」的下标(用到联想时本来就会建,这里不多占内存);每次按键有扫描上限。
- **限制**:首字只取第一段笔画的前 40 个候选,第一段打得太短(一两笔)时,首字不在前 40 的词会漏掉,多打几笔就出来了;只看词库里的词,不造新词。

**繁体字频 + 字形偏好**
- **问题**:以前字频只取自 8105 简体字表,繁体常用字(學、體、國)和没字频的生僻字一样是「没字频」,短前缀下被大量简体字挤到很后面。
- **做法**:笔画词库(`stroke.txt`)多一列「繁体字频」(第 4 列,取自朙月拼音的单字权重)。排序先分字形档(`StrokeRank`):
  1. 偏好字形里的常用字(字频 > 1);2. 另一种字形里的常用字;3. 没字频的生僻字;
  每档里仍是:笔画数刚好 > 字频(2 倍一档)> 精确字频 > 笔画短的;「我选过的」永远在这一切前面。
  - 两边都常用的通用字(人、的)在两种偏好下都是第 1 档,只是同档里看偏好那一边的字频。
  - **设置**:词库管理页新增「笔画字形偏好」:简体优先(默认,和以前顺序一致,只是常用繁体字不再和生僻字挤在一起)/ 繁体优先。下次弹出键盘生效。只影响笔画页(含组词的首字),不影响拼音。
- **要重新下载一次笔画词库**才有繁体字频:词库管理里点笔画词库的下载 / 更新,会顺便取朙月拼音(装过拼音词库就直接用,不重复下载)。没重新下载时,第 4 列没有,排序和以前完全一样(自测里随机比较 4 万对,零差异)。
- **自定义来源**:笔画词库的自定义地址可以写第 3 行(可选)= 繁体字频表(Rime 格式)。手动部署 `stroke.txt` 时,第 4 列(可省略)放繁体字频整数。
- **缓存**:笔画词库的二进制缓存格式升到 2(多存繁体字频),第一次启动自动重建一次。

- 测试:`tools/StrokeWordsSelfTest.java`(每段笔画核对、`*` 和空段、字数不够、首字候选、按分数留前 N、扫描上限、单字和多音字重复不收、速度)、`tools/StrokeRankSelfTest.java`(两种偏好下的字形档、通用字、繁体常用字比生僻字靠前、没有繁体字频时顺序和以前完全一样)。

### 第 13 次(0.28.0):笔画数筛选(整字)+ 长按候选看读音和笔画数

**整字:只要笔画数刚好等于输入的字**
- **问题**:笔画页是前缀匹配,打 4 笔会带出一大堆 5 画、6 画……的字(靠排序把刚好 4 画的排前面,但不能只看它们)。
- **怎么用**:笔画页打了笔画后,右侧功能列的「123」换成「整字」(宽屏数字区在左边,「整字」占空格的一半)。按一下(变蓝),候选只剩笔画数刚好等于输入的字;预览条变成 `一丨丿 ｜整字`。再按一下关掉。
  - 和 `*` 配合就是「已知前几笔 + 总笔画数」:`h*****` = 横开头、一共 6 画的字。
  - 和「分字」配合,每一段都要刚好:`szhs'szhhshhnh`(整字开)= 第一个字刚好 4 画、第二个字刚好 9 画的词。
  - 同一个字有几种笔顺时,各自按自己的笔画数算,任意一种刚好就算。
  - 选了候选、空格上屏、清空,「整字」自动关掉,下一段重新来;随输入一段的开始复位,不会带到下一个字。
- **怎么查得快**:不带 `*` 时编码必须正好等于输入,在按编码排好的表里只是一小段连续区间(比前缀查询还快);带 `*` 时在前缀区间里逐条核对长度。不开「整字」时查询一点没变。
- **代码**:`StrokeEngine.queryExact` / `search(code, exact)`,`StrokeIndex.matchesCp(cp, pattern, exact)`,`StrokeWords.accept(ix, segs, exact)`;键盘 `ActionType.EXACT`;服务 `toggleExact` / `exactActive`(候选的过期判断也带上「整字」开关)。

**长按候选看读音和笔画数(打生僻字时分辨同形字)**
- **怎么用**:拼音页、笔画页(含联想词)长按候选栏里的某个词,在它上方弹出一行信息:`鼗  ·  tao  ·  13 画  ·  一丨丿…`。
  - 读音取自拼音词库,是不带声调的拼音(词库里就是这样);多音字最多列 4 个,用 ` / ` 隔开;词显示成音节之间加空格(`zhong guo`)。
  - 笔画数取自笔画词库(词是各字第一种笔顺的笔画数之和);单字再给出笔顺(一丨丿丶ㄥ)。词库里没有的部分不显示;都没有就提示「词库里没有这个字的读音和笔画」。
  - 5 秒后自动收起,候选一变也收起;表情候选和英文页不适用(英文页长按仍是「固定」菜单)。
- **功耗**:只在长按时才查,而且放在后台线程;用到的那份词库没加载过才加载(提示「加载中,稍后再长按」,加载完再长按一次就有),并随别的词库一起闲置释放。笔画的反查索引和拼音的「按词排序」下标都是按需建一次,和联想、笔画筛选共用,不多占内存。平时不长按,一点开销都没有。
- **代码**:`CandidateBarView.infoHandler` / `showInfo`(和「固定」菜单共用一个弹窗,抽成 `popupAt`);`PinyinEngine.readings`、`StrokeEngine.infoOf`;服务 `requestInfo`。
- 测试:`tools/StrokeWordsSelfTest.java` 增加整字(exact)的前缀 / `*` / 两种笔顺 / 空段 / 分段,以及 `strokeCount`、`firstCode`。
